2026 年初，「養龍蝦」突然變成全民運動。大家在家裡的電腦、迷你主機、雲端主機裝上 OpenClaw，讓它幫忙收信、整理資料、上網爬文，甚至直接操作電腦。

結果沒過幾個月，風向就變了：有人移除、有人擔心資安、有人看著 token 帳單嚇一跳，出現了所謂的**「棄養龍蝦潮」**。同一段時間，另一個開源 Agent **Hermes** 快速竄起，在不少指標上追過了龍蝦。

這篇整理我對這兩個工具的理解：它們差在哪、該怎麼選，以及龍蝦為什麼會被棄養。

## 先說結論

- **OpenClaw 是「平面擴展」**：往外接，接更多聊天軟體、更多 Agent、更多社群技能，追求「什麼都能做」。
- **Hermes 是「垂直擴展」**：往深做，從你的使用習慣中學習、累積技能和記憶，追求「越用越懂你」。
- **兩者能做的事其實差不多**：都能上網爬資料、跑指令、排程、接 Telegram 或 Slack；Hermes 也能透過 MCP 一直加觸手。差別在**怎麼長大**，以及**可不可控**。
- **棄養潮的主因不是龍蝦不夠強，而是太強卻管不住**：權限太大、第三方技能有風險、token 燒很快，加上門檻比想像中高。
- **我自己比較看好 Hermes**：對個人或小團隊來說，一個穩定、會學習、行為可預期的 Agent，比一個什麼都能碰、但難以掌控的 Agent 更實用。

## 先認識兩隻主角

### OpenClaw：那隻紅色龍蝦

OpenClaw 是開源的自主 AI Agent 框架，吉祥物是一隻紅色龍蝦，所以安裝、調教它被大家叫做「養龍蝦」。它在 2025 年底發布，原本叫 Clawdbot，後來改名 Moltbot，最後定名 OpenClaw。

2026 年 1 月底重新發布後爆紅，48 小時內衝到 10 萬顆星，4 月更超過 React，成為 GitHub 上星星最多的專案。創作者 Peter Steinberger 在 2 月加入 OpenAI，專案改由基金會維護。

它的核心是一個**長駐的 Gateway（閘道）**：負責接上各種聊天軟體、管理對話、權限和狀態。你可以在 LINE、Telegram、Slack、iMessage 等 20 幾個平台跟它說話，它再去操作檔案、瀏覽器、終端機，幫你把事情做完。

### Hermes：會自己長技能的 Agent

Hermes Agent 是 Nous Research 做的開源 Agent（MIT 授權）。它最大的特色是**學習迴圈**：

- 完成一個比較複雜的任務後（例如用了很多次工具、中間出錯又自己修好、或被你糾正過），它會把做法整理成**技能（Skill）**，下次直接重用。
- 用不到的技能會慢慢被標記成過期、封存，常用的會被強化。
- 會跨對話記住你的偏好和習慣，越用越像「你的」助理。

它一樣能接 20 幾個聊天平台、有 60 多個內建工具（上網搜尋、瀏覽網頁、看圖等），也能**連接 MCP Server** 擴充能力，指令可以跑在本機、Docker、SSH 遠端主機或雲端沙箱上。

## 平面擴展 vs 垂直擴展

我自己的理解是：**龍蝦往橫向長，Hermes 往縱向長。**

| | OpenClaw（平面擴展） | Hermes（垂直擴展） |
| --- | --- | --- |
| 成長方向 | 接更多平台、更多 Agent、更多社群技能 | 把同一個 Agent 磨得更懂你 |
| 核心架構 | Gateway 優先：先把所有入口接起來 | Agent 優先：先把執行和學習做好 |
| 技能從哪來 | 主要從 ClawHub 安裝社群做好的技能 | 主要從你的使用過程中自動長出來 |
| 記憶 | 跨對話保留資訊，近期加入整理記憶的機制 | 定期反思、全文搜尋舊對話，建立使用者模型 |
| 多 Agent | 強項：可以跨機器開一整支「Agent 軍團」 | 以單一 Agent 加子任務分派為主 |
| 上手感受 | 裝好就有一堆現成技能可以用 | 剛開始很普通，用了幾週才看得出差別 |
| 適合 | 想一次接很多管道、跑很多角色的人 | 有固定重複工作、想要穩定可預期的人 |

用比喻來說：

- **OpenClaw 像是一次請了一整個部門的實習生**，每個人都能做很多事，也能去外面借工具（ClawHub），但你要花很多力氣管理誰能碰什麼。
- **Hermes 像是請了一個會做筆記的助理**，一開始什麼都要教，但教過的事情會越做越好，而且做事方式你大概都猜得到。

## 龍蝦的優勢，為什麼反而變成問題？

龍蝦一開始最吸引人的，就是兩件事：**能自主上網爬各種資料**，以及**能直接控制電腦**。

但這兩個優勢，換個角度看就是風險：

- **能控制電腦 = 權限很大**。它可以讀檔案、開瀏覽器、跑終端機指令、收發訊息。授權只要設錯一次，後果就不是「答錯一句話」，而是真的刪了東西、寄錯信。商業周刊的報導就提到，Meta 有主管因為授權設定錯誤，重要信箱被 AI 清空。
- **能自主爬文 = 會讀到不可信的內容**。網頁裡如果藏了惡意指令（提示注入），Agent 可能會被誘導去做你沒叫它做的事。
- **能裝社群技能 = 供應鏈風險**。ClawHub 上的技能是第三方寫的，惡意技能可能偷跑指令、外洩資料。

也就是說，**龍蝦的問題不是做不到，而是做太多、又管不住**。

## 為什麼會出現「棄養龍蝦潮」？

整理各家報導，原因大致有這幾個：

### 1. 資安和權限失控

除了上面講的權限問題，2026 年 3 月中國工信部也發布風險提示，指出 OpenClaw 預設的安全設定很脆弱，可能越權操作。部分國營企業、政府機關和大學因此限制或禁止內部使用。

### 2. Token 帳單太嚇人

OpenClaw 本身免費，但要接 AI 模型的 API，用多少付多少。它為了「記得事情」，會一直重讀先前的對話和記憶；技能也常常整包塞進上下文。結果是：**一句很短的指令，背後可能燒掉幾萬個 token**。如果再讓它在背景長時間跑自動化，帳單很容易失控。

### 3. 門檻比想像中高

很多人是被「AI 幫你自動做事」的短影音吸引進來的，裝了才發現：要開終端機、要設定 API key、要調權限、技能要手動建立和授權，出問題還要自己看 log。對非工程師來說，這比想像中難很多。

### 4. 移除也不簡單

有報導提到，因為它深入系統運作，刪不乾淨可能讓電腦變慢，甚至留下後門，有人還得花錢請工程師幫忙移除。

### 5. 有更順手的替代品出現

剛好在這段時間，Hermes 的學習迴圈開始被討論。到 2026 年 5 月，Hermes 在 OpenRouter 上每天消耗的 token 量已經超過 OpenClaw，排名第一；而 OpenClaw 在 GitHub 的每週新增星數，從 2 月高峰的每週約 4 萬顆，掉到每週不到 2 千顆。

不過要注意，**OpenClaw 的總星數和下載量仍然遠多於 Hermes**。所謂棄養潮，比較像是熱潮退燒、使用者重新分流，而不是龍蝦被淘汰了。

## 那 Hermes 就比較安全嗎？

不完全是。這點我覺得要講清楚，免得大家從一個極端跳到另一個極端：

- **Hermes 一樣能跑指令、控制電腦**。如果用「本機」模式，指令就是直接在你的電腦上執行。它有危險指令檢查、高風險操作要你批准等機制，但前提是你有好好設定。
- **MCP 觸手也是供應鏈**。每接一個 MCP Server，就等於多給 Agent 一種能力，也多一個可能出問題的入口。來路不明的 MCP Server，風險跟來路不明的 ClawHub 技能是一樣的。
- **自動長技能，代表規則是開發者幫你定的**。什麼時候該存成技能、多久反思一次，都寫死在 Hermes 的設計裡。你省下了手動管理的力氣，但也交出了一部分控制權。

所以 Hermes 比較讓我放心的地方，不是它「做不到危險的事」，而是：**它的能力是透過 MCP 一個一個加上去的，每一隻觸手你都知道是哪來的；它的行為會往你的習慣收斂，比較可預期。**

## 怎麼選？

| 你的情況 | 建議 |
| --- | --- |
| 想在很多聊天軟體上都能叫到同一個助理 | OpenClaw |
| 想同時跑很多個不同角色的 Agent，分散在不同機器 | OpenClaw |
| 想裝好就有一堆現成技能可以玩 | OpenClaw（但技能要自己審） |
| 有固定、重複的工作流程，想讓 AI 越做越順 | Hermes |
| 重視行為可預期、不想被 Agent 嚇到 | Hermes |
| 想用 MCP 一個一個接自己需要的工具 | Hermes |
| 不是工程師，只是想試試 AI 自動化 | 兩個都先別急，先用 ChatGPT、Claude 這類官方 App 的排程、Agent 功能 |
| 處理金融、醫療等敏感資料 | 兩個都不建議直接上線 |

不管選哪一個，有幾個共通的原則：

1. **裝在獨立的環境**：迷你主機、雲端虛擬機或容器，不要裝在你每天工作的電腦上。
2. **權限從最小開始**：先給唯讀，確定沒問題再慢慢開。
3. **技能和 MCP 只裝看得懂、來源可信的**。
4. **設定 token 上限和用量警示**：避免背景任務默默把錢燒光。
5. **重要動作一定要人工確認**：寄信、刪檔、付款，這些都不該讓 Agent 自己決定。

## 接下來的發展

### 1. 從「什麼都能做」走向「做得穩」

第一波大家比的是功能多不多，下一波會比**權限管理、沙箱、審核紀錄**。能說清楚「Agent 做了什麼、為什麼做、誰批准的」的框架，才能進到公司裡用。

### 2. 記憶和自我學習會變成主戰場

Hermes 的學習迴圈證明了「越用越好用」是能留住人的。OpenClaw 這邊也在補，例如會偵測你的糾正、建議建立技能的 Skill Workshop，以及把短期資訊整理成長期記憶的 Dreaming 機制。兩邊會越來越像。

### 3. MCP 和技能標準化，框架差距會縮小

當工具都透過 MCP 接、技能都照共通格式寫，換框架的成本就會變低。到時候選擇的關鍵，會從「功能」變成「生態系、穩定度和維運成本」。

### 4. 成本控制會變成標配

Agent 會一直呼叫模型，成本是最現實的問題。接下來會看到更多「先用便宜的模型判斷，再決定要不要叫大模型」的設計，像我之前寫的 [Jev 這類快速判斷的模型](/posts/what-is-jev/)，就很適合放在 Agent 前面做分流。

### 5. 大廠的官方 Agent 會壓縮自架的空間

ChatGPT、Claude、Gemini 都在把排程、操作電腦、連接外部工具做進自家產品。對一般使用者來說，「自己架一隻 Agent」的必要性會越來越低；自架框架會更集中在工程師、需要高度客製或資料不能出去的場景。

## 結語

養龍蝦的熱潮，某種程度上是大家第一次真正感受到「AI 不只會聊天，還能動手」。棄養潮則是第二堂課：**能動手的 AI，最重要的不是它能做多少事，而是你管不管得住它。**

這也是為什麼我比較看好 Hermes 這種垂直擴展的方向。觸手可以透過 MCP 慢慢加，該爬的資料一樣爬得到，但每一步都在你可以理解、可以預期的範圍內。對大多數人來說，一個穩定的好助理，比一支難以掌控的軍團更有用。
