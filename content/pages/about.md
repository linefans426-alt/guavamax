嗨，我是 GUAVAMAX 的站長，一名有 **十多年實戰經驗**的軟體開發者。

從傳統的網站與後台系統一路做到現在，目前在新創公司負責技術決策與部分經營工作，寫程式之外，也要煩惱架構、維運、預算和團隊溝通。

## 我的技能樹

| 類別 | 經驗 |
| --- | --- |
| **後端開發** | PHP／Laravel 為主力，也寫過 Java、C++，資料庫以 MySQL 為主 |
| **系統與維運** | GCP、虛擬機部署、資安設定、負載平衡 |
| **LINE 應用** | 長期開發 LINE 相關的會員、訊息與互動應用 |
| **AI 應用** | LLM 串接、AI Agent、Gemini CLI、Claude Code、Vibe Coding |

這幾年工作的重心，放在兩件事上：

- **AI 導入應用**：怎麼把 AI 真正接進公司的系統和日常流程，而不只是停在「試玩一下」。從串接 API、規劃架構，到說服老闆和團隊，都是我每天在處理的事。
- **LINE 應用開發**：LINE 在台灣幾乎人人都在用，我持續研究它和 AI 結合的可能性。

除了技術本身，我也很在意**技術怎麼變成商業價值**：一個功能能不能幫客戶多賺一點、一套系統的成本算不算得過來。這也是為什麼這裡除了教學，也會寫產業和商業模式的觀察。

## 我是怎麼樣的人

- **喜歡拆解問題、找出規律**：習慣用結構化的方式看事情，這個毛病不只出現在寫程式。看到夾娃娃機會忍不住研究機台結構，抽一番賞也會想算算機率和規則。
- **不進則退**：遇到瓶頸或產業變化時，我比較習慣的處理方式是去學新工具、做點自己的專案，而不是停在原地焦慮。這個網站本身，就是這樣的產物。
- **在效率和生活之間找平衡**：工作節奏很快，但我也提醒自己保留生活品質和自己的步調。

## 這裡會寫什麼

- **技術案例**：實際做過的功能與系統，包含架構取捨和踩過的坑。
- **AI 應用筆記**：AI 開發工具的安裝、設定與實戰用法，盡量寫成照著做就會成功的步驟。
- **職場與產業觀察**：在台灣推動 AI 導入的真實心得，例如[怎麼向老闆解釋 API 不會被訓練](/posts/why-ai-api-cannot-be-trained/)。
- **像素小遊戲**：放在[遊戲廳](/arcade/)，每款都附開發筆記。

## 為什麼是像素風？

因為我一直保有一顆童心。

從小看著神奇寶貝、遊戲王、七龍珠這些王道動漫長大，到現在還是很喜歡。打開這個網站時，我希望它不只是一個冷冰冰的技術部落格，而是像一台老遊戲機：按下 START，就能開始一段小冒險。所以文章是「存檔點」，閱讀進度是「EXP 條」，讀完一篇會顯示「STAGE CLEAR!」。

工作之餘自己做點小遊戲，對我來說也是保持寫程式樂趣的方式。

## 寫作原則

1. 只寫自己動手驗證過，或真實經歷過的東西。
2. 工具類文章會標註撰寫時間與官方文件來源，版本更新時回頭修正。
3. 步驟寫清楚，讓新手也能跟著完成。
4. 文章內容會使用 AI 協助整理與排版，但觀點、經驗與最後的把關都來自我自己。
